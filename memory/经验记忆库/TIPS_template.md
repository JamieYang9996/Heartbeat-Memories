### ✅ [示例] Python 虚拟环境配置问题

#### **创建时间**
- 问题时间：YYYY-MM-DD HH:MM
- 触发事件：Python 项目依赖冲突，无法正常运行
- 环境：Ubuntu 22.04, Python 3.10

#### **问题描述**
```bash
# 错误现象
$ python app.py
Traceback (most recent call last):
  File "app.py", line 3, in <module>
    import pandas as pd
ModuleNotFoundError: No module named 'pandas'
```

#### **根本原因**
1. 系统 Python 和项目 Python 版本冲突
2. 多个项目共用全局包导致依赖混乱
3. 未使用虚拟环境隔离

#### **解决方案**
```bash
# 1. 创建虚拟环境
python -m venv venv

# 2. 激活虚拟环境
source venv/bin/activate  # Linux/macOS
# 或
venv\Scripts\activate     # Windows

# 3. 安装项目依赖
pip install -r requirements.txt

# 4. 验证安装
python -c "import pandas; print('成功导入 pandas')"
```

#### **验证结果**
- ✅ 虚拟环境创建成功
- ✅ 项目依赖正常安装
- ✅ 应用正常运行
- ✅ 与其他项目隔离，无冲突

#### **经验总结**
1. **最佳实践**：每个项目都使用独立虚拟环境
2. **依赖管理**：使用 requirements.txt 记录精确版本
3. **环境隔离**：避免全局安装，减少冲突
4. **文档记录**：在 README 中说明环境配置步骤

#### **适用场景**
- Python 多项目开发
- 团队协作环境配置
- 生产环境部署准备
- 依赖版本冲突排查

### ✅ [示例] OpenClaw 技能配置优化

#### **创建时间**
- 优化时间：YYYY-MM-DD HH:MM
- 触发事件：OpenClaw 响应慢，功能不全
- 环境：OpenClaw v1.x, Linux 系统

#### **问题描述**
1. 部分技能无法正常触发
2. 工具调用响应时间超过 5 秒
3. 配置文件混乱，难以维护

#### **优化方案**
```json
// config/mcporter.json 优化示例
{
  "servers": {
    "tavily": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-tavily", "你的API密钥"]
    },
    "exa": {
      "command": "npx", 
      "args": ["-y", "@modelcontextprotocol/server-exa", "你的API密钥"]
    }
  }
}
```

#### **实施步骤**
1. **清理旧配置**：删除不用的服务器配置
2. **统一格式**：标准化所有服务器配置格式
3. **性能测试**：逐个测试工具响应时间
4. **文档更新**：记录配置最佳实践

#### **优化结果**
| 指标 | 优化前 | 优化后 | 提升 |
|------|--------|--------|------|
| 平均响应时间 | 4.2秒 | 1.8秒 | 57% |
| 配置可维护性 | 低 | 高 | - |
| 技能可用率 | 70% | 95% | 25% |

#### **经验总结**
1. **配置简化**：保持配置简洁，避免冗余
2. **定期清理**：每月检查并清理不用的技能
3. **性能监控**：记录工具响应时间，及时优化
4. **备份恢复**：配置文件定期备份，便于恢复
